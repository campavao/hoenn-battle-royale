# shot-clock: thirty seconds to choose in a duel, and then the clock forfeits it
# (POK-231, POK-292). Kanto's rule: "the PvP clock forfeits; [the bot one] only spends
# the turn" -- nobody drags an opponent into the fog by sitting on a menu, and an
# opponent who has walked away from the game cannot hold you there for ever by
# auto-choosing at the far end.
#
# shot-clock-pass.txt is the other half: the same clock in a fight nobody else is
# waiting on, where it only costs the turn.
#
# A loopback link battle via the engage (the peer mirrors us); once the action menu is
# up we press nothing.
drain gBrMailbox
wait 30
pokebytes gBrMailbox+0x2018 81 00 00 09 05 00 08 00 BD BB C7 FF
wait 400
# the eyeline only fires in a started match (gBrMatch.phase = BR_PHASE_PLAY)
poke u8 gBrMatch 2
poke u8 gBrNetlink+8 1
pokebytes gBrMailbox+0x1018 02 0E 0B 00 00 01 01 00 09 0F 00 10 00 03 01 01
poke u16 gBrMailbox+0x0C 1
wait 900
shot menu
expect u16 gBrBattle+2 0
# Full HP, not exactly 19: the test mon's IVs come off the RNG at boot, so anything
# that shifts a frame on the way in (POK-256 gave the boot a Pokedex to fill) rolls a
# different Treecko. What this line is for is "undamaged before the turn".
expectge u16 gBattleMons+0x28 19
wait 1900
expectge u16 gBrBattle+2 1
# nothing was hiding the clock: the action menu ran it out in the open
expect u8 gBrBattle+9 0
wait 600
shot after
# B_OUTCOME_WON (1) | B_OUTCOME_LOST (2). Both bits, because a loopback peer mirrors us
# -- our own RUN comes back as theirs, so the engine scores a forfeit on both sides at
# once. Against a real peer it is 2 here and 1 there. What this line holds is that the
# fight was DECIDED rather than run from: B_OUTCOME_RAN (4) is the flee POK-231 allows,
# and a forfeit must never be scored as one.
expect u8 gBattleOutcome 3
# and the fight is over: the session is closed and the field is back
expect u8 gBrNetlink 0
say shot clock forfeits ok
